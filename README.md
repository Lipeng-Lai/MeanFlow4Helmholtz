# MeanFlow4Helmholtz

This repository implements conditional generative models for frequency-domain
Helmholtz scattered wavefields for forward modeling. It contains an FNO
regression baseline, a matched GNO diffusion baseline, and an Improved Mean
Flows model, all operating on factorized 70×70 data with real and imaginary
wavefield channels.

The commands below are run from the repository root.

## 1. Environment and data

The code requires Python with PyTorch, NumPy, SciPy, Matplotlib, PyYAML, and threadpoolctl.
Use the PyTorch build appropriate for the available CUDA device when training.

The generated data are expected in the following layout:

```text
dataset/
├── train/
│   ├── data/background.npy
│   ├── data/velocity.npy
│   ├── label.npy
│   └── models.csv
├── val/
├── test/
│   ├── data/
│   └── models.csv
├── velocity_models/
└── velocity_models_70x70/
```

The factorized Helmholtz dataset is generated according to
[`configs/generate_dataset.yaml`](configs/generate_dataset.yaml):

```bash
python dataset/generate/generate_dataset.py \
    --config configs/generate_dataset.yaml
```

The configuration defines the frequencies, 70×70 grid, source positions,
absorbing boundary, numerical stencil, and dataset split. If the data are

## 2. Train the three experiments

The three experiments use separate configurations and write checkpoints below
`checkpoint/`.

### FNO regression baseline

```bash
python train_fno.py --config configs/fno.yaml
```

### GNO diffusion baseline

```bash
python train_gno.py --config configs/gno_ema999.yaml
```

### Improved Mean Flows

```bash
python train.py --config configs/meanflow_improved_ema999.yaml
```

The configurations define the data roots, model architecture, optimizer,
training duration, EMA decay, validation schedule, and sampling settings.
Training resumes automatically from the latest checkpoint in the configured
output directory when one is present.

Convenience wrappers are also available:

```bash
bash scripts/train_gno.sh
bash scripts/meanflow_improved.sh
```

Set `CUDA_VISIBLE_DEVICES` before invoking a command to choose a GPU, for
example:

```bash
CUDA_VISIBLE_DEVICES=0 python train.py \
    --config configs/meanflow_improved_ema999.yaml
```

## 3. Inference and evaluation

Evaluate the best EMA checkpoint on the validation split with:

```bash
python evaluate_fno.py \
    --config configs/fno.yaml \
    --split val

python evaluate_gno.py \
    --config configs/gno_ema999.yaml \
    --split val

python evaluate.py \
    --config configs/meanflow_improved_ema999.yaml \
    --split val
```

The configurations point to the paired validation arrays. The paper plotting
scripts select the geological and frequency-extrapolation cases separately.
A specific checkpoint can be supplied
with `--checkpoint`:

```bash
python evaluate.py \
    --config configs/meanflow_improved_ema999.yaml \
    --split val \
    --checkpoint checkpoint/meanflow_improved_ema999/model_best.pth
```

Evaluation reports relative \(L_2\) error and grouped metrics in the experiment
`runlog.txt`.

## 4. Reproduce the paper figures

All plotting scripts are under [`paper_plot/`](paper_plot/). They should be
run from the repository root after the required data and checkpoints are
available.

### Method and training figures

```bash
python paper_plot/01_method/plot_method.py
python paper_plot/02_loss/plot_loss.py
```

### Spatial comparison figures

CurveVel-A and FlatFault-A are in-distribution cases; Marmousi and Overthrust
test transfer to unseen geological structures. Generative methods use 1, 2,
4, and 8 sampling steps.

```bash
python paper_plot/03_CurveVel_A/plot_curvevel_a.py
python paper_plot/03_CurveVel_A/plot_residual_steps.py

python paper_plot/04_FlatFault_A/plot_curvefault_a.py
python paper_plot/04_FlatFault_A/plot_residual_steps.py

python paper_plot/05_Marmousi/plot_marmousi.py
python paper_plot/05_Marmousi/plot_residual_steps.py

python paper_plot/06_Overthrust/plot_overthrust.py
python paper_plot/06_Overthrust/plot_residual_steps.py
```

Use `--component imag` with scripts that expose the option to render the
imaginary wavefield component instead of the real component.

### Frequency-generalization figures

The sampling-curve scripts evaluate 8–17 Hz in two rows, with 8–12 Hz above
13–17 Hz. Training includes integer frequencies from 3 to 16 Hz. Frequencies
not stored in the factorized arrays are regenerated by the Helmholtz solver.

```bash
python paper_plot/07_ood_freq/plot_curvevel_a_ood_freq.py --device cuda
python paper_plot/07_ood_freq/plot_flatfault_a_ood_freq.py --device cuda
python paper_plot/07_ood_freq/plot_marmousi_ood_freq.py --device cuda
python paper_plot/07_ood_freq/plot_overthrust_ood_freq.py --device cuda
python paper_plot/07_ood_freq/plot_marmousi_high_freq.py --device cuda
```

The last script produces Marmousi spatial comparisons at 17 and 18 Hz.
Figures are exported as PNG and PDF files beside the plotting scripts.

### Efficiency figure

```bash
python paper_plot/08_effiency/plot_multifrequency_efficiency.py \
    --device cuda
```

Panel (a) compares FNO, diffusion, and Mean Flows inference times. Panel (b)
compares frequency-batched one-step Mean Flows with single-thread and
four-thread CPU numerical baselines over 3–16 Hz (14 frequencies). Timings
are medians of ten measured runs after three warm-up runs. This benchmark
can take substantially longer than the other plotting scripts.

## Repository layout

```text
configs/       Dataset generation, FNO, GNO, and Mean Flows configurations
dataset/       Dataset readers and numerical generation code (data excluded)
diffusion/     Gaussian diffusion implementation and samplers
meanflow/      Mean Flows objectives and samplers
models/        Conditional neural network architectures
paper_plot/    Reproducible paper-figure scripts and exported figures
scripts/       Training, evaluation, and data-generation wrappers
utils/         Data loading, normalization, metrics, and runtime utilities
train*.py      Model-specific training entries; train.py defaults to Mean Flows
evaluate*.py   Evaluation entries; evaluate.py defaults to Mean Flows
```

Dataset arrays and metadata, checkpoints, caches, and runtime logs are
excluded from Git tracking by `.gitignore`. Dataset readers and generation
code remain tracked; data and trained weights should be generated or
obtained separately. Exported paper figures and their summary tables are included.
